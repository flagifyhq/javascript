# node-package-entrypoints — delta spec

## ADDED Requirements

### Requirement: Main entry of `@flagify/node` SHALL be platform-neutral

The published main entry of `@flagify/node` (`dist/index.mjs` and `dist/index.js`, resolved via the `"."` condition of `package.json#exports`) SHALL NOT import any Node standard library module (`crypto`, `node:crypto`, `fs`, `path`, etc.), so that bundlers without Node builtins (Metro / React Native, neutral-platform esbuild) can bundle `@flagify/node` — and therefore `@flagify/react` — without errors.

#### Scenario: React Native app bundles `@flagify/react` successfully

- **WHEN** an app importing only `@flagify/react` (e.g. `useFlag()`, `FlagifyAuthProvider`) is bundled by a bundler that cannot resolve Node standard library modules
- **THEN** the bundle completes without attempting to resolve any Node builtin from `@flagify/node`'s main entry

#### Scenario: Webhook helpers are absent from the root export surface

- **WHEN** a consumer imports `@flagify/node` (root)
- **THEN** `verifyWebhookSignature` and the webhook construct/error/type exports are not present on the root module
- **AND** the barrel `src/index.ts` regenerated by `pnpm run generate` (barrelsby) contains no `./webhooks/*` re-exports

### Requirement: Webhook helpers SHALL be exposed exclusively via the `./webhooks` subpath export

`@flagify/node` SHALL expose the webhook signature verification surface (`verifyWebhookSignature`, construct helpers, webhook error classes, and webhook types) through the subpath `@flagify/node/webhooks`, with working ESM (`import`), CJS (`require`), and TypeScript `types` conditions in `package.json#exports`. Node builtin imports inside this subpath SHALL use the explicit `node:` specifier prefix.

#### Scenario: Server consumer verifies a webhook signature via the subpath (ESM)

- **WHEN** a Node.js ESM consumer runs `import { verifyWebhookSignature } from '@flagify/node/webhooks'`
- **THEN** the import resolves and signature verification behaves exactly as it did from the root export in 1.5.0

#### Scenario: Server consumer verifies a webhook signature via the subpath (CJS)

- **WHEN** a Node.js CJS consumer runs `require('@flagify/node/webhooks')`
- **THEN** the require resolves and exposes the same webhook helpers

#### Scenario: TypeScript resolves subpath types

- **WHEN** a TypeScript consumer with `moduleResolution: "bundler"` or `"node16"` imports from `@flagify/node/webhooks`
- **THEN** `tsc --noEmit` succeeds and the helper signatures are fully typed (no implicit `any`)

### Requirement: CI SHALL fail when a Node builtin enters the main-entry bundle graph

The repository's test suite SHALL include a bundling guard that builds a fixture importing `@flagify/react` against the built `dist/` outputs using a neutral platform (no Node builtins available, none externalized), and SHALL fail if the bundle errors or if any Node standard library specifier (bare or `node:`-prefixed) appears in the main-entry module graph.

#### Scenario: Guard passes on a platform-neutral main entry

- **WHEN** `dist/index.mjs` contains no Node builtin imports
- **THEN** the guard test bundles the `@flagify/react` fixture successfully and passes

#### Scenario: Guard catches a future builtin regression

- **WHEN** any module re-exported from the main entry adds a top-level import of a Node builtin (e.g. `node:fs` via a dependency such as `dotenv`)
- **THEN** the guard test fails before release, identifying the offending specifier
